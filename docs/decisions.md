## 2026-10-04 · Этап 3

### Конвейер меню: задачи очереди, одна страница — одна задача
`InspectMenuPdf` → `RenderMenuPage` × N → `BuildMenuWebPdf` → `CarryOverMenuMarkup` → `FinishMenu` (`app/Jobs/Menu`).
На хостинге очередь запускает планировщик на 50 секунд (`routes/console.php`), поэтому каждая страница —
отдельная задача (~3 с на страницу A3 локально). Прогресс («Страницы: 3 из 8») хранится в `menus.progress_*`,
карточка в админке обновляется сама. Повтор после ошибки начинает заново, но готовые страницы пропускает.
Ошибки, понятные человеку (`MenuPdfException`: «PDF защищён паролем», «битый PDF», «нет программы»),
показываются как есть; остальные — общим текстом, подробности в `storage/logs`.

### Отрисовка: каждый размер из PDF отдельно
1600 px (JPEG q85 + WebP q82, из него WebP 1000 и миниатюра 200), 3200 px (WebP q70), 1800 px для лёгкого PDF
(JPEG q65) — три вызова gs на страницу, как три вызова pdftoppm в старых скриптах. Уменьшение большой картинки
в GD даёт мыло на мелком шрифте. Лёгкий PDF собирается своим кодом (`WebPdfWriter`, перенос из
`build-menu-web.php`). На осеннем меню 2026: 8 страниц за 27 секунд, лёгкий PDF 4,3 МБ.

### Вес картинок: как у старого скрипта, но тяжелее файлов осени на сайте
WebP 1600 px нового конвейера в сумме на 18 % тяжелее, чем файлы осеннего меню на сайте (2,9 против 2,5 МБ
на 8 страниц), 1000 px — на 13 %, 3200 px — так же. Причина не в Ghostscript: старый `new-menu.php` сегодня
дал бы на странице 1 те же 358 КБ (poppler 339, gs 347), а на сайте лежит 292 КБ — осенние файлы делались
как-то иначе. Параметры качества не трогаем; если нужно легче — снижать `webp_quality` со сравнением на глаз.

### Публикация
Опубликовано всегда одно меню. «Снять с публикации» отдельно нет: без меню страница пустая — вместо этого
«Откатить на прошлое меню» (список меню). Запланированное меню публикует `menu:publish-scheduled` (каждую минуту).
Предпросмотр — подписанная ссылка на неделю (`/menu/preview/{id}?signature=…`), с `noindex`, без кэша.

### Загрузка до 100 МБ
Livewire по умолчанию принимает 12 МБ и не умеет загружать частями — поднято до 100 МБ (`config/livewire.php`).
**На хостинге до выкладки** поднять в панели reg.ru `upload_max_filesize` и `post_max_size` до 100M и проверить
`client_max_body_size` nginx — иначе PDF типографии (40 МБ) не загрузится.

### Каркас ресурсов Filament без отдельной страницы просмотра
У меню одна карточка (`EditMenu`): состояние, подписи страниц, кнопки. Редактор разделов — этап 4.

## 2026-10-04 · Этап 2

### Фронт без сборки
CSS/JS старого сайта лежат в `public/assets/` как есть, метка `?v=` берётся из даты файла (`App\Support\Html`).
Vite и Node на сервере не нужны.

### Приёмка: визуально без отличий
`npm run visual` сравнивает старый сайт (тег `legacy-2026-10-04`) с новым: HTML и скриншоты 7 страниц на ширинах
390, 768, 1209 и 1440. Итог: HTML совпадает, **0 отличающихся пикселей** везде. Примеры — `docs/visual/stage2-*.webp`.
`npm run visual:check` проверяет в Chrome консоль без ошибок, ссылку из QR (`/menu.php#supy`), увеличение на
телефоне и 3D-газету на ПК — всё работает.

### Приёмка: Lighthouse не хуже
Lighthouse 12, режим production (`APP_DEBUG=false`, `php artisan optimize`), Herd локально.
Большинство страниц совпадает со старыми или лучше (SEO 92 против 91, галерея 98 против 94). Страница меню — по 5
замеров поочерёдно, медианы:

| | Оценка | FCP | LCP | TBT |
|---|---|---|---|---|
| старый | 87 | 1,07 с | 4,07 с | 75 мс |
| новый | 86 | 1,22 с | 4,21 с | 58 мс |

Разница в пределах шума: у старого сайта оценка меню скачет от 85 до 92. В режиме `local` новый сайт хуже
(FCP 1,5 с): Laravel отвечает за 35–90 мс вместо 8–15 мс, и Boost вставляет отладочный скрипт. На проде
обязательно `APP_DEBUG=false` и `php artisan optimize` — записать в `docs/deploy.md` на этапе 10.
«Best practices» 59 у обоих — из-за http без сертификата локально.

### В git только Claude Code
Правила Boost для Codex и Cursor (`AGENTS.md`, `.agents/`) убраны из git, как и `.cursor`, `.codex`, `.grok`:
в проекте работаем через Claude Code. Локально Boost их по-прежнему создаёт.

## 2026-10-04 · Этап 1

### Подтверждено заказчиком

- Ghostscript вместо poppler — принят. На этапе 3 повторить сравнение на серверном gs 9.27.

### Фронт: собираем локально, Node на сервере не нужен
На сервере Node 10. Рекомендация для этапа 2: CSS/JS старого сайта переносим в `public/assets/` как есть,
с версией `?v=` по дате файла, как сейчас (`inc/_helpers.php`). Тогда собирать нечего. Filament публикует
свои файлы через composer (`filament:upgrade`). Если где-то понадобится Vite — собираем локально и коммитим
`public/build`. Окончательно решаем на этапе 2.

### Хранение файлов меню
- Папка меню — `menus/{id}-{8 случайных символов}` на диске `public`: у каждого меню свои имена файлов,
  кэш браузера не покажет старое меню. Страницы — `{N}-1600.jpg`, `{N}-1600.webp`, `{N}-1000.webp`,
  `{N}-200.webp`, `{N}-3200.webp`, лёгкий PDF — `web.pdf`.
- Исходный PDF типографии — на закрытом диске `local` (`storage/app/private/menus/…/source.pdf`): гостям он
  не отдаётся (ТЗ 5.1).

### Схема: отличия от черновика ТЗ (раздел 6)
- `menus.name` — основа имён файлов из старого сайта (`menu_restaurant_fabrikant2026_osen`), уникальна;
  по ней `legacy:import` находит меню при повторном запуске.
- `menu_sections.slug_locked` — «закреплённый адрес» (ТЗ 4.1).
- `promos.slug` — якорь карточки (`#happyhours`), на него ведёт плашка; `photo_path` + `photo_webp_path` вместо
  одного `photo`; `rows` — список `{label, value}`, чтобы порядок строк был явным.
- `gallery_photos.width/height` — отдельными полями (нужны для `<img>` без скачков вёрстки).
- `menu_lines`, `pages`, `bookings`, `settings`, `activity_log` — на своих этапах (8 отложен, 6, 7, 9).

### Адреса разделов — один в один со старым сайтом
`App\Support\MenuSlug` и `MenuSections` — порт `menu_slug()`/`menu_sections()` из `inc/_menu.php`. Эталон
снят со старого кода в `tests/fixtures/legacy/expected-sections.json`; тест сверяет все 35 разделов
(адрес, страница, название, рамки) и крайние случаи.

### `legacy:import` перезаписывает
Повторный запуск обновляет записи по естественным ключам и пересоздаёт разделы меню. Правки, сделанные в
админке после импорта, он затрёт — команда для переезда, а не для синхронизации. Названия праздников
(в старом сайте их не было) заполняются только пустые.

### Часовой пояс приложения — Europe/Simferopol

`APP_TIMEZONE=Europe/Simferopol`. Ресторан один, админы и гости в одном поясе; дата публикации меню и расписание
акций вводятся по местному времени. Расписание акций всё равно считает время явно в `Europe/Simferopol`, чтобы
не зависеть от настройки.

### Рендер PDF меню: Ghostscript на проде, poppler локально

На хостинге нет poppler, а ImageMagick не может читать PDF: в `/etc/ImageMagick-6/policy.xml` разрешены только
`GIF, JPEG, PNG, WEBP`. Значит, Imagick для PDF не годится, остаётся Ghostscript (`/usr/bin/gs` 9.27) через
`proc_open` (функция не отключена).

Сравнение на странице 3 осеннего меню 2026 (A3, мелкий курсив), локально, gs 10.08 и pdftoppm 25:
- `docs/visual/gs-vs-poppler-3200.png` — копия для увеличения, 3200 px: слева poppler, справа gs;
- `docs/visual/gs-vs-poppler-1000.png` — картинка для телефона, 1000 px.

Разницы на глаз нет; gs быстрее (0,7 с против 1,8 с на страницу 3200 px). Размер gs-картинки по высоте может
отличаться на 1 px (4525 против 4526) из-за округления dpi — при нарезке ориентироваться на фактический размер PNG.
На этапе 3 повторить сравнение с gs 9.27 на сервере.
