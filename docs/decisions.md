### Фронт: собираем локально, Node на сервере не нужен
На сервере Node 10. Рекомендация для этапа 2: CSS/JS старого сайта переносим в `public/assets/` как есть,
с версией `?v=` по дате файла, как сейчас (`inc/_helpers.php`). Тогда собирать нечего. Filament публикует
свои файлы через composer (`filament:upgrade`). Если где-то понадобится Vite — собираем локально и коммитим
`public/build`. Окончательно решаем на этапе 2.

### Хранение файлов меню
- Папка меню — `menus/{id}-{8 случайных символов}` на диске `public`: у каждого меню свои имена файлов,
  кэш браузера не покажет старое меню. Страницы — `{N}-1600.jpg`, `{N}-1600.webp`, `{N}-1000.webp`,
  `{N}-200.webp`, `{N}-3200.webp`, лёгкий PDF — `web.pdf`.
- Исходный PDF типографии — на закрытом диске `local` (`storage/app/private/menus/…/source.pdf`): гостям он
  не отдаётся (ТЗ 5.1).

### Схема: отличия от черновика ТЗ (раздел 6)
- `menus.name` — основа имён файлов из старого сайта (`menu_restaurant_fabrikant2026_osen`), уникальна;
  по ней `legacy:import` находит меню при повторном запуске.
- `menu_sections.slug_locked` — «закреплённый адрес» (ТЗ 4.1).
- `promos.slug` — якорь карточки (`#happyhours`), на него ведёт плашка; `photo_path` + `photo_webp_path` вместо
  одного `photo`; `rows` — список `{label, value}`, чтобы порядок строк был явным.
- `gallery_photos.width/height` — отдельными полями (нужны для `<img>` без скачков вёрстки).
- `menu_lines`, `pages`, `bookings`, `settings`, `activity_log` — на своих этапах (8 отложен, 6, 7, 9).

### Адреса разделов — один в один со старым сайтом
`App\Support\MenuSlug` и `MenuSections` — порт `menu_slug()`/`menu_sections()` из `inc/_menu.php`. Эталон
снят со старого кода в `tests/fixtures/legacy/expected-sections.json`; тест сверяет все 35 разделов
(адрес, страница, название, рамки) и крайние случаи.

### `legacy:import` перезаписывает
Повторный запуск обновляет записи по естественным ключам и пересоздаёт разделы меню. Правки, сделанные в
админке после импорта, он затрёт — команда для переезда, а не для синхронизации. Названия праздников
(в старом сайте их не было) заполняются только пустые.

### Версии: Laravel 13, Filament 5, Pest 5 вместо 12 / 4 / 3

В ТЗ написано «Laravel 12 (последняя стабильная)», «Filament 4», «Pest 3». На 4 октября 2026 последние стабильные —
Laravel 13.34, Filament 5.9, Pest 5.3. Взяли их: смысл требования — последняя стабильная версия, а не номер.

Проверено, что подходит хостингу и плагинам:
- Laravel 13 требует PHP 8.3+ — на хостинге 8.4.25;
- Laravel 13 поддерживает MySQL 5.7+ (документация `database`), на хостинге Percona 5.7;
- `filament-shield` 4.x, `spatie/laravel-settings` + плагин Filament 5, `laravel-activitylog` 5, `laravel-backup` 10
  совместимы с Laravel 13 / Filament 5.

Заказчик подтвердил (этап 1).

### Часовой пояс приложения — Europe/Simferopol

`APP_TIMEZONE=Europe/Simferopol`. Ресторан один, админы и гости в одном поясе; дата публикации меню и расписание
акций вводятся по местному времени. Расписание акций всё равно считает время явно в `Europe/Simferopol`, чтобы
не зависеть от настройки.

### Рендер PDF меню: Ghostscript на проде, poppler локально

На хостинге нет poppler, а ImageMagick не может читать PDF: в `/etc/ImageMagick-6/policy.xml` разрешены только
`GIF, JPEG, PNG, WEBP`. Значит, Imagick для PDF не годится, остаётся Ghostscript (`/usr/bin/gs` 9.27) через
`proc_open` (функция не отключена).

Сравнение на странице 3 осеннего меню 2026 (A3, мелкий курсив), локально, gs 10.08 и pdftoppm 25:
- `docs/visual/gs-vs-poppler-3200.png` — копия для увеличения, 3200 px: слева poppler, справа gs;
- `docs/visual/gs-vs-poppler-1000.png` — картинка для телефона, 1000 px.

Разницы на глаз нет; gs быстрее (0,7 с против 1,8 с на страницу 3200 px). Размер gs-картинки по высоте может
отличаться на 1 px (4525 против 4526) из-за округления dpi — при нарезке ориентироваться на фактический размер PNG.
На этапе 3 повторить сравнение с gs 9.27 на сервере.
